  ### Not a finding — item 2 (`export "${sops_env[@]}"` on an empty array)
  
  Checked; the code is fine, but the guard above it is doing more work than the comment claims. On bash ≥ 4.4 (Arch ships 5.3.20 here), `"${arr[@]}"` on an empty array under `set -u` is **not** an unbound-variable error — it expands to zero words. So `export "${sops_env[@]}"` would become bare `export`, which is not a no-op: it **prints the entire exported environment** as `declare -x NAME="value"` lines on stdout and exits 0. Deploy would then sail on to line 263 and die on `GOOGLE_APPLICATION_CREDENTIALS: unbound variable`.
  
  So the `-gt 0` check on line 255 is load-bearing against an environment dump, not just against a confusing later error. Worth a word in the comment, since "`export` with no args prints the env" is the kind of thing a future edit deletes the guard without knowing.

  ### Not a finding — item 5 (the multi-line guard)
  
  `[ "$(printf '%s' "$val" | wc -l)" -gt 0 ]` is right, and right *because* `$( )` already stripped trailing newlines. Enumerated:
  - `tok123` → `printf '%s'` emits no newline → `wc -l` = 0 → accepted. ✓
  - `tok123\n` from sops → `$( )` strips it → same as above → accepted. ✓ (a `wc -l`-on-the-raw-stream version would have counted 1 and rejected every legitimate token — this is the trap the code avoids)

  - `a\nb` → `wc -l` = 1 → refused. ✓
