  ## IMPORTANT
  
  **1. `issuer` and `bucket` are two independent env knobs addressing one object; nothing checks they agree, and `published()` verifies the one it read rather than the one it wrote.** `install/wif/revoke-kid.sh:31-32`, `:110`, `:128`, `:154`
  
  The script **reads** the JWKS from `$issuer/.well-known/jwks.json` (:110), reduces it, **writes** the result to `$bucket` (:154), and then **verifies** by re-reading `$issuer` (:128). Those are `KO_WIF_ISSUER` and `KO_JWKS_URI`, set independently. I confirmed they are not merely related but exactly derivable:
  
  ```
  gs://${issuer#https://storage.googleapis.com/}/.well-known/jwks.json
    == gs://ko-keys-sauyon/hosts/.well-known/jwks.json   # EXACT match
  ```
  
  Concrete failure: someone points the kit at a second environment with `KO_WIF_ISSUER=…/ko-keys-staging/hosts` and leaves `KO_JWKS_URI` at its default. The script fetches the *staging* JWKS, removes the kid from it, and overwrites the **production** object with the staging key set — so every production kid not also in staging is revoked in one command. `jwks-remove-kid.py` cannot see this: the reduced staging document is perfectly valid on its own, so every refusal passes. And `published()`, the net added specifically to answer "did the right thing happen", reads the *staging* URL and reports a healthy staging kid list while production has been clobbered. There is no detection anywhere in the flow.
  
  The benign form of the mistake is caught by luck — if the target kid is not in the staging JWKS, `jwks-remove-kid.py` refuses. The dangerous form is the plausible one: staging seeded from production, or the same device enrolled in both, so the kid is present in each.
  
  Fix is one line and deletes a variable rather than adding a check:
  ```sh
  bucket="${KO_JWKS_URI:-gs://${issuer#https://storage.googleapis.com/}/.well-known/jwks.json}"
  ```
  — or, if `KO_JWKS_URI` must stay an independent knob, refuse when it disagrees with the derivation.
  
  I am **not** raising this as a blocker for your run, because with neither variable set the defaults are consistent. It is a blocker for the tool shipping as a reusable thing, which is what the header at :8-12 presents it as.
