## What holds up on security
- **The sandbox stays on and fails closed.** No AppRun ships, and the build's `installCheckPhase` fails if one appears. Without AppRun, Orca's CLI never adds `--no-sandbox` (`electron-sandbox-switch.js`). The app's own AppImage `--no-sandbox` path only triggers when `APPIMAGE`/`APPDIR` are set, and nothing here sets them. If user namespaces were unavailable, Chromium would abort with "No usable sandbox" rather than run unsandboxed.
- **The test checks the right things.** Case 5 looks at every renderer in the unit's cgroup: it must be in a user namespace different from the main process, and under seccomp (`Seccomp: 2`). A `--no-sandbox` run fails that check, and so does a run with zero renderers.
- **Regressions the tests would catch:**
  - AppRun kept: the build fails.
  - Pinned trees patched or stripped: the build fails (`diff -r` plus the sha256 pin).
  - The `--ozone-platform=wayland` gating broken: case 2 fails, and so does case 5 (no `DISPLAY`).
  - `FONTCONFIG_FILE` dropped: the DejaVu case fails.
  - `--no-sandbox` added: the renderer case fails.
- **Temp dirs and cleanup are safe.** `mktemp -d` can't come back empty, and the trap stops the unit before `rm -rf "$T"`. The GUI uses its own user-data-dir, HOME and runtime dir. If sway doesn't start, grim fails instead of capturing the live screen.

## Important
**I1. The headless GUI case reaches the live session's D-Bus, ssh-agent and Hyprland** (`tests/orca-gui-unsandboxed.sh:178-181`). A `systemd-run --user` unit inherits the user manager's environment. On shiori that includes:
- `DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus`, a fixed path, so moving `XDG_RUNTIME_DIR` doesn't hide it
- `SSH_AUTH_SOCK` (the TPM ssh-agent)
- `HYPRLAND_INSTANCE_SIGNATURE`
- `XDG_CURRENT_DESKTOP=Hyprland`

The test only overrides HOME, XDG_RUNTIME_DIR, WAYLAND_DISPLAY and DISPLAY. So during a run, Orca's tray icon or a notification could appear on the real desktop. A portal request could also land there. A safeStorage call could reach the real login keyring, either reading or creating an entry, or showing an unlock prompt. Any shell Orca starts gets the real ssh-agent and can control the live Hyprland through `hyprctl`. I didn't see any of this happen; these are the paths that are open. This is separate from the deferred nixGL leak.

Fix: add `--setenv=DBUS_SESSION_BUS_ADDRESS=disabled:` (or run sway under `dbus-run-session`), unset `SSH_AUTH_SOCK` and `HYPRLAND_INSTANCE_SIGNATURE`, and set `XDG_CURRENT_DESKTOP=sway`. No test would catch this today.

## Important
1. **A third pinned set, `resources/ripgrep`, is neither excluded nor checked** (orca.nix:92-98, 122-130). `orcad-template.json` pins `ripgrep/linux-x64/rg` and `linux-arm64/rg` by sha256 with `"packagedRipgrep": true`. Orca's own code says deployed slots take rg from `resources/` and verify it. Both files are static today, so autoPatchelf skipped them and their hashes match.
   - Failure: a version bump ships a dynamically linked rg. autoPatchelf rewrites its loader to a /nix/store path and the build still passes, while orcad slot installs fail verification or remote hosts get a broken rg.
   - Fix: exclude `*/resources/ripgrep`, and have installCheckPhase check every sha256 listed in `orcad-template.json`.
2. **The headless GUI case shares your real session D-Bus** (test:178-181). The user manager exports `DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus`. That is an absolute path, so the private `XDG_RUNTIME_DIR` doesn't cut it off. It also passes on `HYPRLAND_INSTANCE_SIGNATURE`.
   - Failure: the app uses libsecret (`org.freedesktop.secrets`), so each fresh-profile run can write a key into your real keyring. If the keyring is locked, an unlock prompt appears on your real desktop. Notifications or a tray icon would also reach your real desktop.
   - Fix: run sway under `dbus-run-session` or a private bus, and clear `HYPRLAND_INSTANCE_SIGNATURE`.
3. **GPU loading depends on nixGL's `LD_LIBRARY_PATH`, and the dlopen check looks at the wrong file** (orca.nix:58-61; test:157-163). The extra runtime libraries are added only to executables. `libGLESv2.so`, which loads the system GL libraries `libEGL.so.1` and `libGL.so.1`, can only find its own linked X11 libraries. When a library loads another, the search uses the calling library's path, not the executable's. The test checks `orca-ide`'s path, so it passes anyway.
   - Failure: if `LD_LIBRARY_PATH` is ever scrubbed (the deferred leak fix), Chromium quietly falls back to software rendering. No case notices: the render check still sees over 100 colours, and the test's headless sway renders in software (pixman) anyway.
   - Fix: add the runtime library dirs to `libEGL.so`, `libGLESv2.so` and `libvk_swiftshader.so` with `patchelf --add-rpath`, as nixpkgs' electron-bin does, and point the check at `libGLESv2.so`.
4. **A desktop-file `--no-sandbox` would go unnoticed** (orca.nix:86-87; test:61). The `--replace-fail 'Exec=AppRun' 'Exec=orca-ide'` replacement keeps any arguments that follow. Many electron-builder AppImages ship `Exec=AppRun --no-sandbox %U`; this one happens not to. The test uses only the first word of Exec.
   - Failure: after a bump, every desktop or `orca://` launch runs with renderers unsandboxed, while the sandbox case stays green.
   - Fix: assert the exact line `Exec=orca-ide %U` in the build, and have the test launch with the Exec line's arguments.
5. **The SIGTERM case doesn't prove the wrappers `exec`** (test:228-233). The pid it signals is Electron's own whatever wraps it, and a forking wrapper would pass the exit status 0 straight through.
   - Fix: record the pid the sway `exec` starts and assert it equals the window's pid.
6. **The old CLI symlink is about to break, and the CLI starts the unwrapped binary.** `~/.local/bin/orca-ide` points into the `…-extracted` store path, which is no longer in the runtime closure, so the next garbage collection leaves it dangling. Once Orca reinstalls it, `launchOrcaApp` starts `$out/lib/orca/orca-ide` directly: no wayland flag, no `FONTCONFIG_FILE`, no nixGL. Part of this predates the diff. A possible fix is `--set-default ORCA_APP_EXECUTABLE` to the nixGL-wrapped bin, or else adding it to the deferred list next to the bin rename.
