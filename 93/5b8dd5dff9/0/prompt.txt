  ## Important
  
  **I1. `[ -r "$src" ] || exit 0` conflates "this host has no Steam" with "Steam is here but its desktop file moved", and in the second case it leaves a stale override in place forever.**
  
  Two distinct bad states:
  
  - *Silent stop.* If a pacman update renames/relocates `steam.desktop`, or ships it under a different path, the gate fires, the script exits 0, nothing is printed, and launches quietly go back to `/usr/bin/steam` — reintroducing the exact `xdg-user-dir` glibc crash this change exists to fix. There is no signal at all. The repo's own precedent for "is it installed" is `pacman -Qq thermald` (`system/thermald-setup:40`), which *does* distinguish the two; the script's comment claims it uses "the same split" as thermald-setup, but the gate is materially weaker.
  - *Stale override.* If `steam` is removed from `system/packages.shiori`, or from `home.packages` in `home.nix`, `$dst` is never touched again. `~/.local/share/applications/steam.desktop` persists with `Exec=/nix/store/<old-hash>-steam/bin/steam %U`, and because `XDG_DATA_HOME` outranks `/usr/share` it **shadows** the packaged entry. Once old generations expire and GC runs, that store path is gone: clicking Steam in elephant/walker does nothing visible (stderr goes to the journal, not to the user), and `x-scheme-handler/steam` resolves to a `.desktop` whose `Exec` is a dead path. This is the specific robustness property given up by choosing an activation entry over `xdg.dataFile` — hm's `linkGeneration` removes its own orphans; this file has no owner and no removal path.
  
  Both are fixed by the same one-liner: make the "no source" branch a cleanup branch rather than a bare `exit 0` —
  
  ```
  [ -r "$src" ] || { rm -f "$dst"; exit 0; }
  ```
  
  and, if you want the silent-stop signal, also emit a warning when the host is one where Steam is expected.
