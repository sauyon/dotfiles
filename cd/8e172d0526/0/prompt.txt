**Important**
1. **home.nix:1898 (no-Orca text): every normal drovr worktree run gets told it was launched `--no-worktree`.** The text says "If that path is inside this checkout, the run was launched --no-worktree; stop and report…". But drovr always puts a run's worktree at `&lt;repo&gt;/.drovr/wt/&lt;run&gt;` (drovr `cli/src/worktree.rs:24`), so that path is always inside the checkout.
   - **Failure:** on kyuusaku, fujiwara or mari, a driver that never entered its worktree is refused. It runs `drovr path r1`, gets `&lt;repo&gt;/.drovr/wt/r1`, sees it is inside the checkout, and stops to ask for a relaunch. It should have run EnterWorktree on that path. This is exactly the case the hook comment at :1887 describes.
   - **Fix:** say "If that path is this checkout's root itself". For a `--no-worktree` run, `drovr path` prints the checkout root.
   - **Why the test misses it:** tests/claude-main-edit-guard.sh:165,178 only checks the lead phrases. One assertion on the condition's wording would catch it.
2. **home.nix:1898 (no-Orca text): "Otherwise" attaches to the wrong clause.** The sentence "Otherwise EnterWorktree with a name creates one under .claude/worktrees" is meant for agents not in a drovr run. Read in order, it is the else-branch of "if that path is inside this checkout".
   - **Failure:** once #1 is fixed, a drovr agent whose path is outside the checkout is sent to make a new `.claude/worktrees` worktree and abandons its run's worktree.
   - **Fix:** "If you are not in a drovr run, EnterWorktree with a name…".

Depending on the Claude Code version, resuming from there either fails or prints a "cd to the other directory" hint; I couldn't check which without launching claude. Fix: `--arg c "${CLAUDE_PROJECT_DIR:-$cwd}"`.
