     - **What it saves:** at each commit it writes a "checkpoint" (prompts, transcripts, tool activity, touched files) as git refs at `refs/entire/checkpoints/<shard>/<id>`. The commit gets an `Entire-Checkpoint:` trailer. It never adds commits to your working branch.
     - **Storage has changed:** older docs and press describe a single `entire/checkpoints/v1` branch. Older versions also left local shadow branches containing unredacted working-tree contents.
     - **Pushing:** checkpoint refs go out with `git push` by default. That can be turned off with `--skip-push-sessions` or sent to a separate repo with `--checkpoint-remote`. Anyone with repo access can read the full transcripts, and secret redaction is best-effort.
     - **Telemetry:** usage analytics go to PostHog by default. Opt out with `ENTIRE_TELEMETRY_OPTOUT=1`.
     - **Hosted parts:** entire.io (web viewer, cross-repo search, regional mirrors) needs a login. Capturing sessions does not.
     - **Agents:** Claude Code, Codex, Cursor, Copilot CLI, OpenCode, Droid, Antigravity, Pi.
     - **Company:** $60M seed led by Felicis at a $300M valuation, February 2026.

     - **Storage:** line-level authorship goes in git notes under `refs/notes/ai`. Prompts stay in a local SQLite database.
     - **Offline:** "no login required". The only outbound data is error telemetry, which is on by default and can be turned off with `telemetry_oss`.
     - **Teams version:** has a prompt store and can be self-hosted.
     - **Agents:** 12+ local agents, including Claude Code, Codex and Cursor.
     - **Catch:** git notes are dropped by forge squash- or rebase-merges unless you use its CI Actions.
  3. **Cursor's Agent Trace**: a spec only, not a tool. v0.1.0, RFC status, January 2026, CC BY 4.0. It does not say how data should be stored. Listed partners include Cognition, Cloudflare, Vercel, Amp, OpenCode, Jules and git-ai.
     - The `cursor/agent-trace` GitHub repo returned 404, so that link is unverified.
  4. **jj**: Apache-2.0, 32k stars, v0.46.0. It snapshots the working copy and logs an operation every time a jj command runs.
     - Setting `fsmonitor.watchman.register-snapshot-trigger = true` makes it snapshot on every file change.
     - It doesn't know about agents. Linking snapshots to conversations would need something like a Claude Code hook that runs jj after each edit.

     - Gemini CLI has `BeforeTool`/`AfterTool` in `settings.json`. I couldn't confirm whether its hook input includes a transcript path.
     - jj snapshots the working copy at the start of each command, not on a timer.
  2. **Storage: prior art uses two patterns, and neither survives a host squash-merge on its own.**
     - git-ai keeps line ranges in git notes under `refs/notes/ai` (standard v3.0.0) and stores prompts outside git.
     - Entire puts an `Entire-Checkpoint` trailer on each commit and keeps session data in `refs/entire/checkpoints/<shard>/<id>`. That data is pushed by default (`push_sessions: true`).
     - Git itself only copies notes on amend and rebase, and only when `notes.rewriteRef` is set; cherry-pick isn't covered. Notes need explicit push and fetch refspecs.
     - git-ai needs a CI action to restore attribution after a GitHub squash-merge.
  3. **Attribution:** Agent Trace (v0.1.0 RFC) stores line ranges as of the commit that recorded them. To find who wrote a line, you run blame, then look up that commit's ranges; a `content_hash` re-matches code that moved. The spec leaves rebases open. DeltaDB is stronger here because it anchors to a delta rather than a line number.
  4. **Multiplayer:** Loro looks like the best fit, since it has a movable tree type and keeps full history. The only benchmarks I found are from 2024, published by Loro, and disputed by the Yjs maintainers. The hard part is syncing CRDT state with agents writing to disk, which I'd put at months of work.
  5. **Security:** Don't commit transcripts to work repos. They contain full Bash output and file contents, and anyone with read access to the repo sees every git ref, with no way to restrict a single ref. Keep transcripts in a local SQLite file and push only opaque IDs or line ranges. Entire itself calls its redaction "best-effort".
  6. **Effort (my own judgement; I found no published effort data from either project):**
     - MVP (hooks + SQLite + commit trailer + `why file:line` CLI): 2–5 days.
     - Notes that survive rewrites, plus adapters for more agents and redaction: 2–4 weeks.
     - CI re-attachment after squash-merge, plus a shared store: 1–2 months.

  1. **Is Delta unsuitable for work?** Yes, for confidential code.
     - When a thread syncs, Delta uploads the git objects and full file contents, every intermediate edit, and the agent conversation to Zed's Cloudflare backend. You can't choose a region, and the encryption keys are Cloudflare-managed.
     - Telemetry can't be turned off. Sentry crash reports can't either, and they "can contain thread content", so even an unshared thread can leave the machine.
     - Delta is proprietary. Self-hosting isn't on the roadmap, and there is no SOC 2 or SSO yet.
     - The August 2025 promise to open-source DeltaDB hasn't been repeated in 14 months. Zed's existing collab server was never supported for self-hosting.
  2. **Local or self-hostable alternatives:**
     - **git-ai** (Apache-2.0, v1.7.5) is the best fit. It works offline with no login, writes line-level attribution into git notes, keeps prompts in a local SQLite database, and its only telemetry is error reporting, which can be turned off.
     - **Entire CLI** (MIT, still pre-1.0) records full transcripts in git refs. Out of the box it sends PostHog usage analytics and pushes the transcripts on `git push`. It's only safe for work with both turned off.
     - **SpecStory** saves chat logs inside the project folder.
     - **jj's operation log** keeps a history of edits between commits but doesn't know which conversation caused them. I found no tool that links jj operations to agent transcripts.
  3. **Building your own:** my effort figures are estimates, not sourced data.
     - **A basic version takes about 2–5 days.** Claude Code hooks already receive `session_id`, `tool_use_id` and `transcript_path`, so you log those to a local SQLite database, add an opaque session ID to each commit message, and write a `why file:line` lookup command.
     - **Making it survive rebases and squash-merges takes about 2–4 weeks.** Keying on jj change IDs instead of commit hashes avoids much of that work.
     - **Matching DeltaDB's real-time multiplayer would take 3–6+ months** and isn't worth it.
     - **Security:** only opaque IDs and line ranges should ever leave the machine. Transcripts must never go into a work repo, because they contain everything the agent read.
  4. **Recommendation:**
     - Run git-ai locally with telemetry off and no login.
     - Raise Claude Code's `cleanupPeriodDays`, which defaults to 30 days, so the transcripts aren't deleted.
     - Add `PreToolUse`/`PostToolUse` hooks that run `jj debug snapshot` and log each step to local SQLite. This also catches edits made through Bash, which Claude Code's own checkpoints miss.
     - Build more only if git-ai doesn't hold up in colocated jj repos.
