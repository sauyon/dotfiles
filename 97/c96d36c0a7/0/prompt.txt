## Important

1. **The Wayland clipboard helper can't find its library** (orca.nix:55-58). `resources/bin/orca-wayland-clipboard` loads `libwayland-client.so.0` at runtime. After patching, its search path covers only libglvnd, systemd, libsecret, libnotify and libappindicator, plus nix glibc's own directory.
   - My shell turned out to be inside the old bwrap environment, where a fake `/etc/ld.so.cache` and `/lib` hid the failure. The real store path has no cache file, so on the Arch host this load should fail. The unpatched AppImage binary found the host's library. I could not run it on the host itself.
   - Fix: add `pkgs.wayland` to `runtimeDependencies`.
2. **Chromium's audio and video libraries are missing** (same lines). `orca-ide` loads `libpulse.so.0`, `libpipewire-0.3.so.0` and `libva` at runtime, and none of them is reachable now. The old bwrap environment supplied all three.
   - Orca has dictation (`stt-worker`, the sherpa-onnx speech addons) and plays sounds. Without PulseAudio, Chromium falls back to nix's ALSA, which can't use the host's PipeWire/Pulse plugin, so mic and sound likely fail. Screen capture through the portal goes too.
   - Fix: add `libpulseaudio pipewire libva` to `runtimeDependencies`.
3. **nixGL's environment now leaks into host programs** (orca.nix:244). nixGL exports `LD_LIBRARY_PATH` (nix mesa and libglvnd) and several driver variables, and every process Orca spawns inherits them. Inside bwrap that did no harm; now the terminals run host binaries.
   - A host GL program started from an Orca terminal (mpv, chromium, another Electron app) would load nix mesa next to its own libraries. Expect `GLIBCXX` version errors, crashes or the wrong driver. This is inferred; I didn't run it on the host.
4. **Test case 4 (ldd) checks with the wrong loader** (test:126). `ldd` uses its own loader, not the one the binary names (confirmed in `/usr/bin/ldd` at lines 29 and 176). On Arch that loader searches `/etc/ld.so.cache` and `/usr/lib`, so a library dropped from the search path still reports as found if Arch has it installed. It also can't see runtime-loaded libraries, which is why items 1 and 2 pass.
   - Fix: run each file's own interpreter (`LD_TRACE_LOADED_OBJECTS=1 "$interp" f`) and add explicit checks for the runtime-loaded libraries.
5. **Losing `--ozone-platform=wayland` passes the default run** (test:156). Only case 6 starts the app in GUI mode, and it needs `ORCA_TEST_GUI=1`. Case 2 only checks that node mode doesn't get the flag. The uncommitted headless-sway version of case 6 would catch this once committed.

## Nits

- **N1** (orca.nix:60-63). The comment saying the fixup steps run "by hand, or not at all" around the pinned trees is wrong. Shebang patching and rpath shrinking still run over them. They change nothing today only because the two scripts with shebangs (`orcad-template/out/cli/index.js`, `runtime.py`) aren't executable. Test 5 would catch a change.
- **N2** (orca.nix:40-43). AppRun added `--no-sandbox` when user namespaces were unavailable. That fallback is gone, so on such a host Chromium aborts on the non-setuid `chrome-sandbox`. Fine on this Arch host.
- **N3.** There is no `wrapGAppsHook3`, so GSettings schemas and GIO modules come from the host's `/usr/share`. The GTK file chooser fallback works only if the host has gtk3's schemas. Desktop launches also get no `LOCALE_ARCHIVE` for nix glibc.
- **N4** (test:71). `nix-store -qR | grep -q` under `pipefail` can report "no bubblewrap" when bubblewrap is present: `grep -q` exits early, nix-store gets SIGPIPE and the `else` branch passes. It doesn't happen today only because the 14 KB listing fits in the pipe buffer.
- **N5** (test:84). Only `ELECTRON_RUN_AS_NODE=1` is tested, not empty or `0`.
- **N6** (test:94). `date +%Z` passes on a UTC host whatever the build does. The `readlink /etc/localtime` check covers it.
- **N7** (test:102-110). The font cases run the host's `fc-list`/`fc-match`, not Electron's own built-in fontconfig. They do still fail if `FONTCONFIG_FILE` is dropped.
- **N8** (test:113-117). In the node-pty case, output can arrive after the exit event and print `" 0"`. That is a flaky false failure, not a false pass.
- **N9** (test:120-125). If `file` isn't on the host, the message says "only 0 ELFs found", which is misleading. It still fails.
- **N10** (test:140). `diff -r` ignores file modes, so a lost exec bit on node would pass case 5. The modes are correct today.
- **N11** (test:68, 161-199). If `mktemp` fails, `"$T/home"` becomes `/home`. The exit trap doesn't stop the test's systemd unit, so an interrupted run leaves a second Orca running on a profile being deleted.
- **N12** (test:78). Finding the app directory depends on `nix-store -qR` listing the inner package before the nixGL wrapper, which also contains `lib/orca`. It works today.
