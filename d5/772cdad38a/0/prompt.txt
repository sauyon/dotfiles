## Important
**I1. On Orca hosts, a phase agent in a run that is already isolated is told to stop the run** (`home.nix:1900`, Orca text)
- **Scenario:** the run was launched correctly from `~/orca/workspaces/dotfiles/&lt;task&gt;`, or with `drovr new --worktree`. A phase agent there edits the primary checkout by absolute path. That is plausible in this repo, because the auto-mode text names "the dotfiles repo at ~/devel/dotfiles".
- **What it's told:** "drovr phase agent, do not move: stop and report that the run must be relaunched from an Orca worktree".
- **What happens:** following that halts a healthy run. The driver then relaunches from an Orca worktree the run is already in. The right action is to edit the same file inside its own worktree.
- **On hosts without Orca:** the same agent is told to EnterWorktree on `drovr path &lt;run&gt;`, which is the directory it is already in. The retry is refused again, so it loops instead of halting.
- **Overlap:** this is close to the decided item "an agent already in a worktree told to make another", but the result here is a stopped run. Drop it if you count it as covered.
- **Fix:** add one clause: "if your working directory is already a linked worktree, edit this file's counterpart there."

## Nits
1. **The `--no-worktree` test compares exact strings** (`home.nix:1900`, no-Orca text). `drovr path` prints the launch directory or `--dir` argument as typed, without canonicalizing it (drovr `main.rs:1420-1438`, `cmd_path` at `:1592`).

   - `--resume` has explicit handling for sessions recorded in a worktree, so the suggested command very likely still works. I didn't run it because it would start a session.
   - The `.cwd` fallback is effectively never reached for local hooks.
